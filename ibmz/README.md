# IBM Z / s390x Secure Execution (SE) PodVM Packaging

This directory contains tooling for packaging `dm-verity` protected s390x PodVM images into hardware-encrypted **IBM Secure Execution** (`.protvirt`) boot images for Confidential Containers (CoCo).

---

## Architecture & Modes

On x86_64, `scripts/verity/verity.sh` signs a Unified Kernel Image (UKI) cmdline addon with a Secure Boot key and uploads it to Azure Compute Gallery (`azure/upload-azure.sh`).

On **IBM Z (`s390x`)**, `ibmz/build-se-podvm.sh` accomplishes the exact equivalent, with support for **two deployment paths**:

### Path A: Direct SE Kernel Boot (Standard for CoCo / CAA)
1. Extracts `vmlinuz` and initramfs from the read-only root partition (`vda2`) of the `qcow2`.
2. Assembles the kernel cmdline with the `roothash`:
   ```text
   root=/dev/mapper/root roothash=<HASH> systemd.verity_root_data=/dev/vda2 systemd.verity_root_hash=/dev/vda3 systemd.volatile=overlay rd.driver.pre=overlay console=ttysclp0 ro panic=0
   ```
3. Generates a standalone hardware-encrypted `.protvirt` boot image with `genprotimg`.
4. The `.protvirt` is passed to Libvirt as `<kernel>` and the `qcow2` as `<disk>`.

### Path B: Self-Contained "All-in-One" QCOW2 (Single Volume Upload)
1. Generates the `.protvirt` image as described in Path A.
2. Writes the `.protvirt` image directly into the **PReP boot partition (`vda1`)** of the `qcow2` image using `guestfish` / `zipl`.
3. **Preserves `dm-verity`:** The root partition (`vda2`) and verity hash tree (`vda3`) are never modified.
4. The resulting `qcow2` can be uploaded to a storage pool / cloud registry and booted with standard disk boot (`<boot dev='hd'/>`) with no external kernel parameters.

---

## Prerequisites

- `s390-tools` (or package containing `genprotimg`)
- `libguestfs-tools` / `guestfs-tools` (`guestfish`)
- Target IBM Z Host Key Document (`.crt` / `.pem`) from the host machine or IBM Resource Link
- The `qcow2` image and sidecar generated by `scripts/create-verity-podvm-s390x.sh`

## Usage Examples

```bash
chmod +x ibmz/build-se-podvm.sh

# 1. Path A: Standalone .protvirt image (passing a folder of host keys)
./ibmz/build-se-podvm.sh \
  --host-key /etc/se-keys/ \
  --cert-repo /etc/se-keys/crls/ \
  /path/to/rhel10-s390x-base.qcow2

# 2. Path B: All-in-One Self-Contained QCOW2 Image (passing a folder of host keys)
./ibmz/build-se-podvm.sh \
  --host-key /etc/se-keys/ \
  --cert-repo /etc/se-keys/crls/ \
  --write-to-disk \
  --disk-out /path/to/rhel10-s390x-se-allinone.qcow2 \
  /path/to/rhel10-s390x-base.qcow2
```

### Options

| Flag | Env Variable | Description |
|---|---|---|
| `-k, --host-key <PATH>` | `HKD_PATH` | Path to IBM Z Host Key Document (HKD) file (.crt/.pem) OR folder containing host keys. Can specify multiple times. |
| `-c, --cert-repo <PATH>` | `CERT_REPO_PATH` | Path to HKD Certificate Authority / CRL directory. |
| `-r, --roothash <HASH>` | `ROOTHASH` | Manually specify roothash (defaults to `<IMAGE>.roothash`). |
| `-o, --output <PATH>` | `OUTPUT_PROTVIRT` | Destination `.protvirt` path. |
| `-w, --write-to-disk` | | Embed `.protvirt` into `vda1` of the target QCOW2 disk. |
| `--disk-out <PATH>` | | Destination path for the modified QCOW2 (if omitted, writes in-place). |

## Libvirt XML Configurations

### Path A: Direct SE Kernel Boot
```xml
<domain type='kvm'>
  <name>coco-podvm-se</name>
  <memory unit='MiB'>2048</memory>
  <vcpu>2</vcpu>
  <os>
    <type arch='s390x' machine='s390-ccw-virtio'>hvm</type>
    <kernel>/path/to/rhel10-s390x-base.protvirt</kernel>
  </os>
  <devices>
    <disk type='file' device='disk'>
      <driver name='qemu' type='qcow2'/>
      <source file='/path/to/rhel10-s390x-base.qcow2'/>
      <target dev='vda' bus='virtio'/>
      <readonly/>
    </disk>
    <console type='pty'>
      <target type='sclp'/>
    </console>
    <vsock model='virtio'>
      <cid auto='yes'/>
    </vsock>
  </devices>
</domain>
```

### Path B: All-in-One Disk Boot
```xml
<domain type='kvm'>
  <name>coco-podvm-se-allinone</name>
  <memory unit='MiB'>2048</memory>
  <vcpu>2</vcpu>
  <os>
    <type arch='s390x' machine='s390-ccw-virtio'>hvm</type>
    <boot dev='hd'/>
  </os>
  <devices>
    <disk type='volume' device='disk'>
      <driver name='qemu' type='qcow2'/>
      <source pool='default' volume='rhel10-s390x-se-allinone.qcow2'/>
      <target dev='vda' bus='virtio'/>
      <readonly/>
    </disk>
    <console type='pty'>
      <target type='sclp'/>
    </console>
    <vsock model='virtio'>
      <cid auto='yes'/>
    </vsock>
  </devices>
</domain>
```
